# Les missions d'Albert — parcours de transition SNT → Première NSI

## Principe
Chaque notion est découverte dans un défi visuel, expliquée par une prédiction, appliquée dans le code, vérifiée sur plusieurs cas et réinvestie sans guidage. Le tuteur propose une question ou un indice, jamais la solution complète.

## Parcours A — Instructions et algorithmes (missions 01–04)
Séquences, ordre d'exécution, orientation, décomposition, débogage. Validation : expliquer un trajet et corriger une instruction.

## Parcours B — Boucles bornées et variables (missions 05–08)
Affectation d'une valeur à une variable de type entier, boucle bornée `for`, `range`, trace d'exécution, répétitions. Validation : prédire le nombre d'itérations.

## Parcours C — Structures conditionnelles (missions 09–16)
`if`, `else`, `elif`, booléens, comparaisons, `and`, `or`, conditions imbriquées, combinaison avec `for`. Validation : identifier la branche exécutée et proposer des cas de test.

## Parcours D — Python réel et données (à construire)
`print`, `input`, conversions `int`/`float`/`str`, types, opérations, chaînes, indexation, listes, parcours, `len`, `append`, `in`, accumulateurs. Exécution impérative par Pyodide isolé et tests automatiques.

## Parcours E — Boucles non bornées (à construire)
`while`, condition d'arrêt, compteur, sentinelle, risque de boucle infinie, limite de temps. Exécution isolée avec interruption et tests de terminaison.

## Parcours F — Fonctions et préparation NSI (à construire)
Définir une fonction avec `def`, paramètres, `return`, distinguer afficher et renvoyer, annotations simples, tests avec `assert`, cas limites, débogage, petits projets.

## Exigences de validation
- Aucun défi « réussi » sur la seule présence textuelle d'un mot-clé : contrôler la trace, les résultats et plusieurs entrées.
- Pour les missions de conditions, vérifier ultérieurement les branches vraie et fausse sur des jeux de données distincts.
- Ne pas présenter l'interpréteur limité actuel comme Python complet.
- Conserver le site et les 150 défis existants.
- L'image de puce BD fournie doit remplacer le pictogramme CSS provisoire dans la grille et l'animation d'absorption.
- La clé API Albert reste exclusivement côté serveur ; aucune donnée personnelle dans le dépôt public.
- Publication et validation visuelle sur GitHub Pages avant usage en classe.
